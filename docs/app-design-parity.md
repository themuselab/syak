# 소비자 웹 · 앱 디자인 통일

2026-11-08, 소비자 앱의 현재 구현(`Syak_FE`)을 기준으로 웹을 맞췄다. 이전 PNG 시안보다 최근 앱의 `SearchBar`, `CategoryChipBar`, `FilterChipBar`, `ShopListCard`, `ShopDetailBody`와 공용 테마 토큰을 우선했다.

## 화면

- 홈: 44px 검색바, 프로필, 시술 분야·파트너샵 칩. 분야 선택 시 검색바가 선택한 분야 헤더로 바뀌며 해제할 수 있다.
- 목록: 기본 40% 높이 시트, 28px 모서리, 시트 안의 당일 예약·할인·정렬·가격·시간 필터. 매장 이름/메타 → 오늘 시간 → 112×150 사진 → 리뷰 미리보기 순서다.
- 상세: 흰색 헤더 → 22px 제목/지역·리뷰 → 126×152 사진 → 홈·가격·예약·리뷰 탭. 탭 이동과 스크롤 위치를 연결했다. 하단에는 앱과 같은 48px 녹색 예약 버튼과 보조 연락 버튼을 둔다.
- 필터: 정렬, 0~10만원 가격 범위(10은 상한 없음), 오늘·내일·모레와 시간. 웹의 기존 분야·시술·혜택 조건은 펼쳐서 사용할 수 있다. 지역 선택도 유지한다.
- 데스크톱: 900px 이상에서 검색·목록 38%와 지도 나머지 영역을 flex로 배치한다. 목록은 전체 높이를 채우며 사진과 상세·필터 패널도 화면 폭에 맞춘다. 모바일에서는 전체 폭과 기존 바텀시트를 사용한다.

## 동작과 데이터

- 공개 `/web/shops/*` 목록·핀 API를 유지한다. 앱의 공개 `/shops` 배치 응답에서 같은 샵 ID의 사진 3장·리뷰·오늘 시각을 보충한다(배치당 최대 100건). 보충 실패 또는 해당 응답에 없는 샵은 기존 대표사진과 정보로 표시한다. 카드마다 상세 API를 호출하지 않는다.
- 네이버 사진은 앱과 같은 `search.pstatic.net/common`의 `f300_400` 프리셋으로 축소한다.
- 가격 범위는 매장의 대표 최저가 `minPrice` 기준이며, 가격 미상은 범위 지정 시 제외한다. 시간 선택은 기존 예약 슬롯 조회를 사용한다.
- 공개 웹에 회원 인증을 새로 만들지 않았다. 프로필·즐겨찾기·파트너샵 빈자리 알림은 기존 앱 웹의 해당 화면으로 연결한다. 웹에서 즐겨찾기를 저장했다고 표시하지 않는다.
- 지도 기본 중심은 앱과 같은 강남역이다. SDK가 늦거나 차단되어도 기본 목록을 조회한다. 지역·파트너·이름 검색 흐름을 유지한다.
- GA/GTM/Hackle 전송, `shop_type`, 네이버 이동 이벤트, 기기 ID 분배, 실험 5·플래그 4·원격 문구를 유지한다. A 문구는 기존 서버 라벨을 유지하고 B 문구는 기존 원격 구성에서 받는다. 공통 디자인 변경 시점 이전/이후는 분석에서 구분한다.

## 검증

`npm run test:catalog`는 가격 경계·미상 가격·상한 없는 범위 3개 사례를 확인한다. 기존 `npm run test:analytics` 8개도 함께 실행한다. TypeScript, lint, Vercel 웹 빌드와 Toss 빌드를 확인한다. 실제 브라우저 확인은 설치된 Google Chrome을 사용한다.

로컬 주소에서는 네이버 지도 서비스의 도메인 인증이 제한될 수 있으므로, 지도 자체는 운영 도메인에서도 확인한다. Toss 미니앱 출시는 별도 배포 절차다.

검증 완료: 가격 필터 3개·analytics 8개 통과, TypeScript 통과, lint 오류 0(기존 경고 1개), 웹/Toss 빌드 통과. Chrome 360×800·390×844·1280×900에서 상세 탭·필터 적용·고정 하단·가로 넘침을 확인했다. SDK 인증 실패 시에도 검색·목록·필터가 유지되도록 인증 실패 콜백과 지도 오류 경계를 추가했다.
